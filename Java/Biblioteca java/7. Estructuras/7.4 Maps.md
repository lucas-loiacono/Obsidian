## Gemini

## 1. Declaración y Genéricos (Dos tipos de datos)

Como un mapa vincula una Clave con un Valor, al instanciarlo tenés que decirle a Java qué tipo de objeto será la clave y qué tipo de objeto será el valor. Al igual que con las listas, **solo acepta objetos (clases envolventes), nunca primitivos**.

Supongamos que querés modelar una base de datos rápida en memoria para buscar un Pokémon usando su número de Pokedex. La clave será un `Integer` (el ID) y el valor será un `String` (el nombre).


```Java
import java.util.Map;
import java.util.HashMap;

// Map<Clave, Valor> nombre = new HashMap<>();
Map<Integer, String> pokedex = new HashMap<>();
```

- **Regla de oro de las Claves:** Las claves son **únicas e irrepetibles**. No podés tener dos elementos con la clave `25`. Los valores, en cambio, sí pueden repetirse (podrías tener varios Pokémon tipo "Agua").
    

## 2. El Arsenal de Métodos (Operaciones del Mapa)

Los mapas no usan `.add()`, usan `.put()`.

**Inserción y Actualización (Create / Update)**

- `pokedex.put(25, "Pikachu");`: Guarda el par en el mapa.
    
- `pokedex.put(25, "Raichu");`: **Ojo acá.** Si la clave `25` ya existía, Java no crea un registro nuevo; va y **sobrescribe** el valor anterior. El `25` ahora apunta a "Raichu".
    
- `pokedex.putIfAbsent(25, "Pikachu");`: Método moderno muy útil. Solo lo inserta si la clave `25` está libre.
    

**Lectura y Búsqueda (Read)**

- `pokedex.get(25)`: Le pasás la clave y te devuelve el valor (`"Pikachu"`). Si la clave no existe, devuelve `null`.
    
- `pokedex.containsKey(150)`: Devuelve `true` si existe la clave 150 (Mewtwo) en tu mapa. Es una operación **instantánea**.
    
- `pokedex.containsValue("Charizard")`: Devuelve `true` si algún registro tiene ese valor. (Esta operación es lenta porque tiene que revisar uno por uno).
    
- `pokedex.size()`: Te dice cuántos pares Clave-Valor hay guardados.
    

**Eliminación (Delete)**

- `pokedex.remove(25)`: Borra el registro completo (la clave y su valor) asociado al ID 25.
    

## 3. Iteración: Cómo recorrer un Mapa

Como los mapas no tienen un orden secuencial (no hay posición 0, 1, 2), no podés usar un bucle `for` tradicional. Java te ofrece tres formas de extraer la información para recorrerla con un `for-each`:

**Opción A: Recorrer solo las Claves (`keySet`)**

Útil si solo te importan los identificadores.

```Java
for (Integer id : pokedex.keySet()) {
    System.out.println("ID del Pokémon: " + id);
}
```

**Opción B: Recorrer solo los Valores (`values`)**

Útil si las claves no te interesan en ese momento.


```Java
for (String nombre : pokedex.values()) {
    System.out.println("Nombre: " + nombre);
}
```

**Opción C: Recorrer ambos a la vez (`entrySet`)**

Es la forma más eficiente y profesional cuando necesitás imprimir o procesar el par completo. Un `Entry` es la "caja" que contiene la Clave y el Valor pegados.


```Java
for (Map.Entry<Integer, String> registro : pokedex.entrySet()) {
    System.out.println("ID: " + registro.getKey() + " - Nombre: " + registro.getValue());
}
```

## 4. El Secreto del HashMap: ¿Por qué es tan rápido?

Si tenés un `ArrayList` con un millón de usuarios y querés saber si existe el usuario "Lucas", Java tiene que buscar desde la posición 0 hasta la 999,999 uno por uno. Esto se llama costo lineal u $O(n)$.

El `HashMap` utiliza una técnica matemática llamada **Hashing**. Cuando hacés `mapa.put("Lucas", objetoUsuario)`, Java toma la palabra "Lucas", la pasa por una función matemática (Hash) y la transforma directamente en una dirección de memoria.

Cuando después hacés `mapa.get("Lucas")`, repite el cálculo matemático y va **directo a la caja exacta** sin revisar ninguna otra. El costo computacional es $O(1)$, es decir, instantáneo, sin importar si hay 10 elementos o 50 millones.
